    The story

    Problem and approach

    The problem

    A blocked scammer simply tries the next number, and nobody learns how the scam works. Keeping scammers busy with a bot protects real people for as long as it lasts and leaves a record of exactly what they ask for.

    What I built

    Each incoming message is scored for scam signals. A rule-based selector then changes the bot's style: passive at first, vulnerable when scam risk climbs, stalling once enough details are collected. An AI persona served by Groq writes the replies. Payment and contact details are pulled out with pattern matching and shown on a live dashboard.

    How it is built

    How it works

    1. 01

      A FastAPI backend scores each message against known scam signals

    2. 02

      A rule-based selector moves the bot through four styles: passive, engaged, vulnerable and stalling

    3. 03

      A persona written by an AI model on Groq replies, and sees the last 10 messages

    4. 04

      Pattern matching pulls out UPI IDs, links and phone numbers, each with a fixed confidence level per pattern type

    5. 05

      A filter for prompt-injection attempts and a per-visitor request limiter

    6. 06

      A live React dashboard, interactive API documentation (Scalar) and a Docker setup

    Results

    What it showed

    Every number comes with how it was measured. The limits are part of the result.

    • The bot's style changes automatically as scam risk and collected details grow
    • UPI IDs, links and phone numbers are saved as structured threat information
    • Request limit of 1 per second per visitor, with bursts of 5
    • The persona sees the last 10 messages for each reply
    • A live dashboard shows warning signals, the current style and the details collected

    FAQ

    Questions about this project

    Who built which part?

    It was co-built with Prasanna Patil. My side was hardening and the AI layer: the filter for injection attempts, the request limiter, the move from Gemini to Groq and the persona prompts. Prasanna wrote the first version, the Docker setup and the README.

    How well does it resist prompt injection?

    It has a keyword filter and a request limiter. That is a first line of defence, not a complete solution, because a determined attacker can word a trick in ways a keyword list misses. A client project would add a proper test suite of attack attempts.
