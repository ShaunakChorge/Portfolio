    SMS spam classifier project built with Naive Bayes

    A spam filter with zero false alarms on its test set.

    This SMS spam classifier project is a small, early-stage build from an AICTE internship on AI. Using TF-IDF word scores and Naive Bayes, it labels a text message as spam or not spam. Built from 5,169 labelled messages, it scored 97.1% accuracy with no false alarms on 1,034 test messages, and a Streamlit page shows the label.

    Overview

    Why this matters

    Teams that handle many incoming messages, such as a support desk or a shared inbox, lose time to spam, and scam messages put customers at risk. A trained text model can screen messages before a person reads them, so staff spend their time on the genuine ones. The harder part is doing that without hiding a message someone needs.

    A good result is a filter that rarely blocks a genuine message, says how many spam messages it still misses, and can be retrained on a team's own labelled messages. This project is a small first version of that: a cleaned dataset, a measured model and a page where anyone can paste a message and see the label.

    The story

    Problem and approach

    The problem

    Spam text messages waste time and carry scams. Checking each one by hand does not scale, and a filter that wrongly blocks a genuine message does more harm than one that misses a few spam messages, because the reader never sees what was blocked. The aim was to teach a small model to tell the two apart, and to measure how often it makes each kind of mistake.

    What I built

    Following a public tutorial, I started from a labelled collection of 5,572 text messages and removed 403 repeats, which left 5,169. I cleaned each message with NLTK: lowercase, split into words, keep letters and digits, drop very common words and cut words to their roots. TF-IDF then scored the 3,000 most frequent words, and a Multinomial Naive Bayes model learned from a random 80% of the messages. I tested it on the other 20%, 1,034 messages, and saved the model and word scores to files. A Streamlit page and a command-line script load those files, repeat the same cleaning and show Spam or Not Spam.

    What made it hard

    1. 01

      Few spam examples

      Only 653 of the 5,169 cleaned messages, about 13%, are spam. A model can look accurate by calling everything genuine, so accuracy alone says little.

    2. 02

      Messy message text

      Messages use abbreviations, numbers, symbols and odd spelling. The raw file also had 403 repeated messages and three mostly empty extra columns. All of it needed cleaning before any model could learn from it.

    3. 03

      Blocking a real message

      A false alarm hides a genuine message from its reader, which costs more than a missed spam. The model had to be judged on both kinds of mistake, not on one score.

    4. 04

      Same cleaning in the page

      The page must clean a pasted message exactly as the training messages were cleaned. Any difference would mean scoring words the model never saw, and the measured results would no longer apply.

    How it is built

    How it works

    1. 01MessagePasted into the page
    2. 02Clean textLowercase, drop filler, cut to roots
    3. 03TF-IDF scores3,000 words, each weighted
    4. 04Naive BayesDecides spam or not spam
    5. 05LabelSpam or Not Spam shown
    1. 01

      A file of 5,572 labelled text messages. Three mostly empty extra columns were dropped and 403 repeated messages removed, leaving 5,169: 4,516 genuine and 653 spam.

    2. 02

      Each message is made lowercase and split into words with NLTK (a Python toolkit for text). Punctuation and symbols are dropped, very common words (stop words) are removed, and words are cut to their roots with the Porter stemmer, so loving becomes love.

    3. 03

      A TF-IDF vectoriser (scikit-learn) keeps the 3,000 most frequent words and scores each one by how often it appears in a message and how rare it is across all messages.

    4. 04

      A Multinomial Naive Bayes classifier, a simple method that compares how often each word appears in spam and in genuine messages, with default settings. It learns from a random 80% of the messages (4,135); the other 20% (1,034) is kept for testing, split once with a fixed seed.

    5. 05

      On the 1,034 test messages the confusion matrix shows all 896 genuine messages passed, 108 of 138 spam messages caught and 30 missed. That gives accuracy 97.10%, precision 100% and recall 78.26%.

    6. 06

      The trained word scores and model are saved as two pickle files (Python's way of storing objects), each under 100 KB, so the page and the script load exactly what was tested.

    7. 07

      A Streamlit page titled Email/SMS Spam Classifier, though only text messages were used, has a text box and a Predict button and shows Spam or Not Spam. A command-line script, predict.py, does the same for one message. Both repeat the cleaning steps first.

    Decisions

    Design decisions and trade-offs

    • Remove repeats before splitting

      ChoiceI removed 403 repeated messages before splitting the data, rather than leaving them in.

      WhyA message that appears in both the training and test sets would be recognised, not judged, and would lift the score. Removing repeats first keeps the test fairer.

    • Put precision first

      ChoiceIn the model comparison I ranked models by precision and kept one that blocked no genuine message, over several with higher accuracy.

      WhyA blocked genuine message is lost without its reader knowing, while a missed spam is only an annoyance. Precision and recall are reported next to accuracy because accuracy alone hides this.

    • Multinomial Naive Bayes over other models

      ChoiceFollowing a public tutorial, I kept Multinomial Naive Bayes after a longer working notebook scored 14 other models and combinations on the same split, including Bernoulli Naive Bayes (98.4% accuracy, 1 false alarm).

      WhyOnly it and nearest-neighbour search flagged no genuine message, and it was far more accurate than that one (97.1% against 90.5%). The saved model is also small, under 100 KB.

    • Save the model, reuse the cleaning

      ChoiceI saved the trained word scores and model to files and repeated the exact cleaning steps in the page, rather than retraining or cleaning differently when the page starts.

      WhyThe page always uses the exact objects that were tested, and a pasted message is cleaned like the training messages, so the measured scores still apply.

    Results

    What it showed

    Every number comes with how it was measured. The limits are part of the result.

    Results

    • 97.10% accuracy on 1,034 test messages, a random 20% of the cleaned data, measured once in the notebook.
    • 100% precision: none of the 896 genuine test messages was flagged as spam, so there were no false alarms.
    • 78.26% recall: 108 of the 138 spam messages in the test set were caught and 30 were missed.
    • A filter that never flagged anything would still score 86.7% on this test set, because 896 of its 1,034 messages are genuine. That is why precision and recall are reported next to accuracy.
    • In the longer working notebook, 15 models and combinations were scored on the same split. Only two flagged no genuine message, and this one was the more accurate of the two.
    • The formal project report gives no accuracy number, so every figure on this page comes from the notebook output.

    Limits to keep in mind

    • Text messages only, in one language. No email was used for training or testing, so email accuracy is unknown. Emails are longer and carry subjects, links and attachments, so an email filter would need its own labelled data.
    • One dataset, one random split. The test result is a single measurement, and the word scores were learned from all messages before the split, so the figure is slightly optimistic. Newer scam wording would need fresh data.
    • It misses about one spam message in five (30 of 138 on the test set). A real filter would need a cut-off the owner can tune, a review folder for flagged messages and regular retraining on new messages.
    • It is a local demo: no automated tests, no monitoring, no link to any messaging system, and the requirements file pins older library versions than the ones that saved the model files.

    FAQ

    Questions about this project

    How does a spam classifier for text messages work?

    A spam classifier turns a message into numbers and lets a trained model decide whether it looks like spam. Here the text is cleaned, each word is scored with TF-IDF, and a Naive Bayes model, trained on 4,135 of 5,169 labelled text messages, answers Spam or Not Spam.

    How accurate is this spam classifier?

    On 1,034 held-out text messages it scored 97.10% accuracy, 100% precision and 78.26% recall: no genuine message was flagged and 30 of 138 spam messages were missed. It is one random split of one dataset, so new messages, other languages or email could score differently.

    What do precision and recall mean for spam?

    Precision is the share of flagged messages that were truly spam. Recall is the share of all spam that was found. Here, on the test set, precision is 100%, so no genuine message was flagged, and recall is 78.26%, so about one spam message in five got through. A useful filter needs both numbers, not accuracy alone.

    Did you compare Naive Bayes with other models?

    The notebook in the public repository trains only Multinomial Naive Bayes. A longer working notebook, kept outside the repository, scored 15 models and combinations on the same split. Only two flagged no genuine message, and I kept Naive Bayes because it was the more accurate of those two.

    Can this spam classifier filter my company's email?

    Not as it stands. It learned from text messages only, so email was never tested. For email I would collect labelled examples of your own mail, retrain the model and measure precision and recall on messages it has not seen, before any message is blocked automatically.

    Is the spam classifier ready for production?

    No. It is an early-stage project built for an internship programme: one dataset, one test split and a local demo page. A production filter also needs fresh data, regular retraining, monitoring, a review queue for flagged messages and automated tests. I can build those around the model.

    Where did the spam classifier project come from?

    I was the only author, with 20 commits. It was the project for the AICTE internship on AI delivered with TechSaksham, a Microsoft and SAP CSR initiative, under the programme's project guide. It follows a public tutorial, and it was submitted with a formal report that gives no accuracy figure.
