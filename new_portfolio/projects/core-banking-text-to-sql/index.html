    Text-to-SQL LLM assistant for core banking

    Everyday questions in, working database queries out, all on the bank's own servers.

    This text-to-SQL LLM (AI language model) assistant at Claptek runs on the bank's own servers. It turns plain-language reporting questions into working Oracle database queries (SQL) over a large core-banking database. My part was the accuracy measurement and the self-correction loop.

    The story

    The problem: answers locked in a huge database

    The problem

    Simple scoring said the query writer was about 93% good. Actually running its queries showed the honest figure was close to zero.

    What I built

    I built the measurement first: a test that runs each generated query and compares the returned rows with a known-correct query. Then I added a retry loop, limited to two passes, that shows the AI the real error and asks for a fix. The client allowed no larger model and no retraining.

    How it is built

    How a question becomes a checked SQL query

    1. 01

      Search over a 1,628-table core-banking database to find the right tables (built by my teammate)

    2. 02

      An AI language model hosted on the bank's own servers writes the Oracle query. The query safety guard and test data were also built by my teammate

    3. 03

      An accuracy test that runs each generated query on a real database and compares the rows with a known-correct query

    4. 04

      A self-correction loop, limited to two passes, that feeds real query errors back to the AI

    5. 05

      A glossary of real code values added to the prompt, so filters use values that actually exist

    6. 06

      Fully on the bank's own servers: no data, prompt or usage record leaves the machine

    Results

    Results from running the queries

    Every number comes with how it was measured. The limits are part of the result.

    • Accounts found rose from 34% to 54%, and the correct share of results from 19% to 27%, with no model change and no retraining
    • 100% of 40 held-out test queries were valid against the live database layout

    FAQ

    Questions about text to SQL

    What is text to SQL?

    Text to SQL means asking a database a question in everyday words and having an AI language model write the SQL query that answers it. The query is then run against the database. The hard parts are choosing the right tables and checking that the query is correct, which is why this project measures results by running queries.

    Is text to SQL safe for a bank database?

    It can be, with controls. Here the AI model runs on the bank's own servers, so no data, prompt or usage record leaves the machine. A query safety guard also checks queries before they run. My teammate built that guard; I built the accuracy test that compares returned rows with a correct query.

    How do you measure whether the generated query is right?

    By running it. The accuracy test executes the generated query on a real database and compares the rows with a known-correct query. This replaced simple scores that had overstated quality, which is why recall and precision are reported from real query results.

    Does any data leave the machine?

    No. The assistant runs fully on the bank's own servers, so no data, prompt or usage record leaves the machine. The AI model is hosted there too, so no online AI service is involved. For a new client, we would first check that your servers are strong enough to run the model.
