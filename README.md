# Shaunak Chorge - Portfolio

Personal portfolio of **Shaunak Chorge**, AI and Python developer (Pune / Mumbai, India).
Live: <https://shaunakchorge.github.io/Portfolio/> - Code: <https://github.com/ShaunakChorge/Portfolio>

A single-page, dark "neural neon" site: glowing cyan / magenta / purple outlines on pure black, Orbitron display type, an animated grid with drifting orbs, a numbered section rail, project cards with generative visuals and a detail dialog, an experience timeline and a contact form.

It is **static HTML, CSS and vanilla JavaScript**. No framework, no bundler, no CDN scripts, no runtime dependencies (fonts are self-hosted, icons are an inline SVG sprite). It works from `file://` and from a GitHub Pages sub-path because every URL is relative.

## Highlights

- Sections: Home, About, Build, Stack, Work, Journey, Contact (left rail + header nav with a sliding indicator, scroll-progress hairline).
- Command palette (`Ctrl/Cmd + K`), accent-colour switcher, project filter chips and detail dialogs.
- Accessible by design: skip link, landmarks, visible focus rings, keyboard-operable widgets, `prefers-reduced-motion` honoured (no parallax, typing, marquee or canvas motion), automated checks with axe-core against the WCAG 2.2 AA rules and a contrast review of the text colours.
- Responsive from 320px to 2560px, light on mobile (heavy effects are off on small / coarse-pointer devices).
- SEO and sharing: canonical URL, Open Graph / Twitter card (`assets/img/og-image.png`, 1200x630), JSON-LD, sitemap, web manifest and a standalone `404.html`.

## Structure

```
index.html              the page you open: generated by build.mjs from src/ (never edit it directly)
404.html                standalone neon 404 (inline CSS, no JS)
build.mjs               assembler (plain Node, no dependencies)
src/                    the page source: shell.html (head, header, rail, section markers) + one HTML partial per section
assets/
  css/base.css          tokens, reset, typography, layout, components (single cascade layer)
  css/sections/*.css    one file per section / feature (hero, about, projects, ...)
  js/core.js            window.Portfolio API: reveal, count-up, scroll-spy, menu, toast, store
  js/sections/*.js      one IIFE per section / feature
  fonts/                Orbitron, Space Grotesk, Space Mono (latin woff2, self-hosted)
  img/                  favicon.svg / .ico, apple-touch-icon, PWA icons, og-image, project + portrait images
  Shaunak-Chorge-Resume.pdf
site.webmanifest  robots.txt  sitemap.xml  .nojekyll
old_portfolio/          the previous site, kept untouched for reference
```

## Run locally

No install step is needed.

```bash
# option 1: just open index.html in a browser (works from file://)
# option 2: any static server, for example
python -m http.server 4173      # then open http://localhost:4173/
# or
npx serve .
```

## Edit content, sections and the build

`index.html` is the output of `node build.mjs` (plain Node, no dependencies), which stitches `src/shell.html` and the section partials together and auto-links the CSS and JS files. The partials in `src/` are the source of the page: edit them, never `index.html`. (Some partials were originally produced by helper scripts that are not part of this repository; the partials themselves are ordinary hand-editable HTML.)

- **Change text or markup:** edit `src/<section>.html` (`hero`, `marquee`, `about`, `services`, `stack`, `projects`, `journey`, `contact`, `footer`), then run `node build.mjs`.
- **Change styling or behaviour:** edit `assets/css/sections/<name>.css` and `assets/js/sections/<name>.js`. Site-wide tokens (colours, type scale, spacing) and shared components live in `assets/css/base.css`; shared helpers are in `assets/js/core.js` (`window.Portfolio`).
- **Add a section:** create `src/<name>.html`, add a `<!-- @section:<name> -->` marker to `src/shell.html` inside `<main>`, and drop `assets/css/sections/<name>.css` / `assets/js/sections/<name>.js` next to the others (they are linked alphabetically, after `base.css` / `core.js`). Give the `<section>` an `id` and a `data-rail="NN·label"` to appear in the left rail.
- **Preview a subset while working:** `node build.mjs --only=hero,marquee --out=preview-hero.html`, then delete the preview file before committing.
- **Minified build (what the live site ships):** `npm i -D esbuild`, then `node build.mjs --min` writes `assets/dist/site.min.css` (all CSS, one file) and one `assets/dist/js/<name>.min.js` per script, and links those instead of the readable sources (plain `node build.mjs` keeps linking `assets/css` and `assets/js`). Scripts are deliberately not concatenated — one big script is one long main-thread task. Commit the generated `assets/dist/` together with `index.html`.
- **Images:** keep them as WebP/AVIF with explicit `width` / `height`; the social image is a static PNG (design it as an HTML page and screenshot it at 1200x630).
- **Colour meaning:** cyan = AI / LLM / agents, magenta = computer vision / media, purple = ML / data / speech, blue = backend / web / tooling.
- **Contact form:** posts to a Formspree endpoint configured in `src/contact.html`; enable spam protection and a domain allow-list for the live origin in the Formspree dashboard.

## Repository layout

- `new_portfolio/` - the current site (everything below: `index.html`, `assets/`, `src/`, `build.mjs`, `site.webmanifest`). Run all build commands from inside this folder.
- `old_portfolio/` - the previous site, kept unchanged and still served at `/Portfolio/old_portfolio/`.
- Repo root - `index.html` (redirect to `new_portfolio/`), `404.html`, `robots.txt`, `sitemap.xml`, `.nojekyll`, this README.

## Deploy on GitHub Pages

1. Repository `ShaunakChorge/Portfolio` -> **Settings -> Pages** -> *Build and deployment*: **Deploy from a branch**, branch `main`, folder `/ (root)`.
2. Commit and push (`git add -A`, `git commit`, `git push`). The site goes live at <https://shaunakchorge.github.io/Portfolio/> within a minute or two.
3. `.nojekyll` makes Pages serve the files as-is, and Pages automatically uses `404.html` for unknown URLs.
4. **Keeping `old_portfolio/`:** it stays in the repo as a plain folder (reachable at `/Portfolio/old_portfolio/`, not linked from the new site). If it still contains its own `.git` directory from an earlier clone, delete that directory first so Git tracks its files instead of treating it as an embedded repository.
5. The canonical URL, Open Graph image URLs, `sitemap.xml`, `robots.txt` and `404.html` use the absolute address `https://shaunakchorge.github.io/Portfolio/`. If the repository is renamed or a custom domain is added, update those (search for `shaunakchorge.github.io`) and rebuild. Note that crawlers only read `robots.txt` at a host root, so on a project site it is informational; the sitemap can also be submitted in Search Console.
6. Social platforms cache link previews; after changing `og-image.png`, refresh the preview with each platform's debugger.
